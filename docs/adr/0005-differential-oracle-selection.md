# ADR-000005: 差分テスト基準器の選定を通常ADRへ委ねる憲法改正

## コンテキスト

[ADR-000001（憲法）](0001-constitution.md) の第5条と第7条3項は、差分テストの基準器（オラクル）を wasmtime と名指ししている。一方、第7条4項は実装を Wasm 1.0 相当から始めると定めている。したがって Phase 0 の差分テストが比べるのは「1.0 の規則で同じ判定になるか」である。

2026-11-15 のロードマップレビューは、wasmtime を 1.0 相当に絞り切れないと指摘した。根拠は [wasmtime issue #3969](https://github.com/bytecodealliance/wasmtime/issues/3969) で、sign-extension と nontrapping float-to-int には無効化用の `Config` オプションが無いとメンテナが述べている。1.0 に無い命令を受理する基準器と比べると、Modal One が仕様どおり拒否したモジュールを基準器が受理する。その差分が「仕様の版の違い」なのか「実装の誤り」なのかは、結果だけでは区別できない。

同日に docs.rs の最新版で確認できたのは次の2点である。

- wasmi の [`Config`](https://docs.rs/wasmi/latest/wasmi/struct.Config.html) には `wasm_sign_extension`／`wasm_saturating_float_to_int`／`wasm_mutable_global`／`wasm_multi_value`／`wasm_bulk_memory` の個別トグルがある。
- wasmtime の [`Config`](https://docs.rs/wasmtime/latest/wasmtime/struct.Config.html) には、sign-extension と saturating float-to-int の個別トグルが無い。ただし低水準の `Config::wasm_features(flag, enable)` があり、ドキュメントは「パーサに拒否させたい機能を無効にする」用途を認めている。これで 1.0 相当に絞れるかは未検証である。

どの実装をどの範囲の基準器にするかは、ツールの版と機能トグルに左右される運用上の選択である。憲法が特定の実装名で固定すると、この選択を変えるたびに憲法改正が要る。

## 決定事項

### 1. 憲法第5条・第7条3項の部分改正（憲法第8条に基づく手続き）

[ADR-000004](0004-target-x86-64-kvm.md) 決定1と同じ手続きを取る。正本である `0001-constitution.md` は直接編集しない。グラフ上は `depends-on` で接続し、改正内容は本文に記録する。

- **改正対象1 — 第5条「借りてよい（器具）」の末尾**:
  - **変更前**: …CI・ビルド補助、そしてwasmtime本体 — wasmtimeは**差分テストの基準器（オラクル）**および**設計の参照（教科書）**として用いる。
  - **変更後**: …CI・ビルド補助、そして**差分テストの基準器（オラクル）**および**設計の参照（教科書）**として用いる既存の Wasm ランタイム（wasmtime、wasmi 等）。どの実装をどの対応範囲の基準器にするかは、検証体制の ADR（[ADR-000003](0003-verification-and-ci.md)）で定める。
- **改正対象2 — 第7条3項（正しさの二本柱）**:
  - **変更前**: 公式スペックテストスイートの合格と、wasmtimeとの差分テストの一致をもって正しさの根拠とする。
  - **変更後**: 公式スペックテストスイートの合格と、基準器（第5条）との差分テストの一致をもって正しさの根拠とする。

### 2. 改正しないもの

- **第5条の判定基準（実行パスか、器具か）**。基準器は器具であり、実行パス（`modal-one-core`）の依存には現れない。
- **差分が出たときの判定順**（[ADR-000003](0003-verification-and-ci.md) 決定3）。正はまず仕様書とスペックテストで判定する。基準器は仕様そのものではない。

### 3. 基準器の割り当ては ADR-000003 に置く

本 ADR が決めるのは、選定の置き場所だけである。対応範囲ごとの割り当てと、機能を絞る方法の検証は [ADR-000003](0003-verification-and-ci.md) 決定3で定める。

## 影響・トレードオフ

**得るもの**: 対応範囲（Wasm 1.0、および個別に採用した 2.0 以降の機能）ごとに、その範囲へ機能を絞れる基準器を選べる。基準器側の版が上がって機能トグルが変わっても、憲法を改正せずに ADR-000003 の更新で追随できる。

**受け入れるもの**: 基準器が複数になりうるので、版の固定と結果の読み方が増える。README の「wasmtime を差分テストの基準器とする」という記述も、本 ADR に合わせて更新する必要がある。
